# 作文批改与学情咨询 —— 优化需求说明（含实现要点）

> 版本：v1（2026-09-17）
> 状态：需求定稿，待实现
> 范围：对现有 AiTeachers 项目（用户注册/登录、作文批改工作台、AI 咨询）做布局与功能优化。**已拍板的取舍见「二、总体决策」**，其余规则为约束补充。

---

## 一、目标与原则

1. 保留项目已有且稳定好的能力，不做重复建设；改动集中在"批量批改、MD 导出、多改写方案、咨询切片与学情、页面布局"。
2. 前端所有后端请求沿用**相对路径 + Nginx 同源反代**，不改 VITE_API_BASE。
3. 数据归属沿用 `X-Username`（owner=提交者/租户，student=作文所属学生）。
4. 全程禁止模拟/随机数据；失败即失败（failed 记录可读原因、可重试）。
5. 严格禁止内置/非原作文内容的指令注入影响评分（沿用现有 prompt 加固）。

---

## 二、总体决策（已拍板）

| # | 议题 | 结论 |
|---|------|------|
| D1 | 详细评分维度 | **收敛为固定五维：内容 / 结构 / 立意 / 语言 / 书面** |
| D2 | 批量批改数据模型 | **批量 = 生成 N 条独立批改记录，前端按「批量任务」聚合**（丢弃"6 图塞进单记录"方案）|
| D3 | 咨询"最近 N 篇" | **默认最近 3 篇，做成可配置项** |
| D4 | 导出范围 | **MD 与 PDF 仅在「批改结果页」提供**（不做批量合并导出）|

## 三、页面布局

- 顶部导航栏（全局）。
- 顶部下方分两栏：左侧边栏 + 右侧功能内容区。
- 侧边栏入口：
  - **开始批改** → 批改提交页
  - **批改结果** → 批改结果列表/详情页
  - **学情报告** → 学情查询页（与用户界面"查学情"同一入口）
- **仅登录取用**：未登录访问上述页一律重定向登录页。
- **咨询页与批改入口物理隔离**：咨询页路由不挂任何上传组件/批改表单。

## 四、批改界面

### 4.1 开始批改

**单次批改**
- 提交一篇作文：图片**最多 3 张**（复用现有 `MAX_PAGES=3`），或正文直输，或 PDF。
- 字段：年级（必填）、体裁（可选）、题目、题干要求、正文/图片、学生归属（可选，缺省=owner）。

**批量批改**
- **最多 2 篇同时批改、单次请求最多 6 张图片**（每篇 ≤3）。
- 数据模型（D2）：后端把一次批量请求拆成 **2 条独立记录**，各自走
  `queued → recognizing → grading → done` 自己的流水线；
  前端用一个"批量任务"容器聚合 2 条结果分别展示。
- 后端为批量请求设**活跃任务并发上限**（默认 2），防止 AI 限流/超时堆叠。
- 批量中任一记录失败：仅该条 `failed`，其余照常完成，返回各自 error 原因。

### 4.2 批改结果（详情页展示项）

- 作文信息：图片数量、选定的作文图片、作文字数、题目、年级。
- 评分：**固定五维分数 + 总分 + 等级（优/良/需改进）**。
- 总评、分项建议。
- 好词（≤5 个，点睛的词）、好句（≤4 个，勾连/点题句）。
- 错词错句（确定性的错别字与语病，保守策略，不作为全量枚举承诺）。
- 开头与结尾**各 3 个**改写候选。
- 作文润色（复用现有 `polished_title/polished_text`）。
- AI 原始结果（`ai_result`）与人工修改（`result`）分离展示，可审计、可回滚。

### 4.3 AI 结果数据结构（schema）改造 —— 本次核心变更

对现有 `review_grader.py` 的权威 schema 做如下调整，**四处同步改齐**：
1. 评分维度固定为 `maxima` = 内容 / 结构 / 立意 / 语言 / 书面（五维）。
2. `rewrites` 改为：
   ```json
   {
     "title": "候选标题（1 个）",
     "opening": ["开头候选 1", "开头候选 2", "开头候选 3"],
     "ending":   ["结尾候选 1", "结尾候选 2", "结尾候选 3"]
   }
   ```
   - prompt 明确为"3 个不同思路的候选"；沿用「不得逐字照抄原文超 12 字」防呆校验。
   - 允许"思路方向 + 一段示范"结构；漏生成时前端给 `N/A` 兜底，不硬凑。
3. `highlights`：按句照抄原文，数量**不硬卡 5/4**，不足时概括"亮点不足"。
4. `corrections`：只列**确定**错别字/语病，提示"字迹/标点以图片识别为准"。

同步更新的四件套（缺一不可）：
- `review_grader.py`（schema、prompt、`validate_result` 校验、维度完整性校验）
- 前端批改结果渲染（五维 → 卡片、rewrites 数组 → 3 选 1 平铺）
- MD 导出模板（见第五节）
- 存量记录兼容：旧 `ai_result` 无新结构时，前端做字段降级映射，不因渲染崩溃。

### 4.4 人工修改

- 沿用现有 `/api/review/{rid}/save`：改分数/总评/各分项建议。
- 保持乐观锁（`version`）+ `ai_result`/`result` 分离 + 手工 `marks` 独立保存。
- 校验：修改后的各维分之和仍须落在评分标准对应卷类区间，避免破坏等级一致性。

### 4.5 作文润色

- 复用现有 `polished_title / polished_text`，不改功能，仅纳入结果页排版。

## 五、导出（仅批改结果页，D4）

- 统一由一份"结构化报告对象"渲染：**先出 MD，再由 MD → PDF**，保证两套导出同源、零漂移。
- **MD 模板**：
  ```md
  # 用户名 作文原标题 分数
  ## 总评
  [总评内容]
  ## 建议
  [根据评分标准给出]
  ## 详细评分
  [内容方面]
  [结构方面]
  [立意方面]
  [语言方面]
  [书面方面]
  ## 好词好句
  [好词；好句]
  ## 错词错句
  [错别字与语病句]
  ## 改写开头与结尾
  [三个开头]
  [三个结尾]
  ```
- **PDF**：MD → PDF。服务器（尤其 Linux）需预置**中文字体**，避免导出乱码。
- 导出文件名来自作文原题，做**路径/非法字符安全处理**，中文用 UTF-8。

## 六、咨询界面

- **能力**：利用批改结果切片入知识库，RAG 对话；不承载批改。
- **切片入库**：仅对 `status==done` 的已完成批改结果建索引（现有防错：跳过 queued/failed）。
- **学情注入**：默认取**最近 3 篇**（D3），改 `review_index.recent_essays` 的 `[-5:]` 为**可配置项 `MOST_RECENT_ESSAYS`（默认 3）**；仍在向量 `top_k=3` 检索之上注入。
- **学情报告能力**：平均分/最高/最低/最近一次、成绩趋势（最近 N 次 vs 此前）、近期篇章列表——复用现有 `build_student_profile`。
- **行为重申（约束严格落实）**：该页为只读；路由**不下发任何上传/批改接口**；后端咨询路由不做作文校验，杜绝越权批改。

## 七、用户界面

- 注册 + 登录（沿用现有 `/register`、`/login`、bcrypt + JWT）。
- 登录后可查看学情报告，数据按 `owner`/`student` 隔离，沿用 `X-Username`。

---

## 八、约束清单

- 严禁任何模拟数据。
- 批量并发上限 = 2；失败单条不拖垮整批。
- 五个维度之和必须落在评分标准对应卷类区间（一类 50~45…，参照加分/扣分微调，总分≤50）。
- 改写防呆：任何候选不得逐字照抄原文超 12 字。
- 好词好句/错词错句**保守不凑数**；识别置信受限时明确提示，不沉默或断言。
- 咨询只读；咨询页零批改入口。
- 导出 MD/PDF 同源；中文文件名安全化。
- 批量/导出涉及 schema 变更时四件套同改、存量降级兼容。

## 十、待实现时的注意点（风险预判）

1. `rewrites` 数组化 + 五维收敛是核心 schema 变更，`review_grader.py`、前端渲染、MD 导出、存量兼容**必须同步**。
2. 导出 PDF 在 Linux 端需中文字体（`fontconfig` + 中文字体），仓库内提前规划。
3. 批量后台并发用现有 `threading` 模式扩展，但需加并发闸与单条失败隔离。
4. 维度口径变更会改变"总分=各维和"与评分标准的映射，须经真实作文回归，避免计分与标准脱节。
